Data handling

Stash keeps clipboard history and snippets available on the user's devices. This policy explains the difference between local storage, private iCloud synchronization, and file reference metadata.

What Stash stores

Stash stores the clipboard content that the user chooses to keep, including history items, snippets, favorites, text, rich text, images, file references, folders, multiple-copy groups, and media metadata. Clipboard content is stored locally on the user's device by default.

On macOS, the optional automatic clipboard saving switch is a per-device setting. When it is off, newly copied items are ignored for automatic history saving on that Mac. Explicit actions such as saving a snippet or choosing a copy/save action remain user-controlled.

Permissions and device access

On iOS, Stash reads the general pasteboard only when the user opens Stash or uses a save or paste workflow. iOS may show a paste permission prompt; Stash does not monitor every copy action in the background.

On macOS, automatic paste uses the Accessibility permission to send Command-V to the previously active app. This permission is used for that paste action and does not send clipboard content to a Stash server.

When Touch ID unlock is enabled on macOS, its local unlock key is stored in this Mac's Keychain and is not synchronized. Sensitive snippet decryption still depends on the local authentication flow.

Three storage categories

01 / Body

Original content stored in Stash

Some text, rich text, and supported images are retained in local app storage according to the platform's size and type rules. Eligible text, rich-text, and image payloads may also sync through iCloud. Video, audio, and imported file bodies remain local-only.

02 / Local only

Original content stored locally, not synchronized

Some large or platform-specific bodies remain only on the device where they were captured or saved. They are not uploaded to CloudKit, but remain usable there while the local data is available.

03 / Reference

Reference metadata only

For many files, folders, packages, archives, media, fonts, Office/iWork documents, and code files, Stash keeps metadata instead of copying the original body. These reference-only entries remain on the saving device: they are not uploaded to CloudKit or displayed on other devices. This can include a display name, extension, type identifier, source app or device, original URL, and security-scoped access information when available.

Per item

Classification is not extension-only

The storage category is decided per clipboard item. The same extension can be classified differently when the source provides text, image data, or a file reference.

A byte count shown in a preview is the stored body size for content saved in Stash. For metadata-only items, it is the size of the metadata record, not the size of the original file.

Platform-specific behavior

macOS

File references stay tied to the source Mac

Image files in supported formats up to 100 MB are stored as image data and may sync. Most non-image file histories, including PDF, SVG, archives, fonts, audio, video, Office/iWork documents, folders, packages, and code/text files, keep the original-location metadata and local access data instead of copying the file body into Stash. Rich text over 10 MB is kept locally while its plain text can remain syncable.

iOS / iPadOS

Accessible file bodies can be kept locally

When iOS provides an accessible file URL or file representation, Stash can copy PDF, SVG, archives, fonts, audio, video, Office/iWork/OpenDocument documents, EPUB, code/text files, and other files into local Stash storage. These local file bodies are used for pasting on that device, but are not uploaded to other devices. Videos and audio remain local-only.

Video saves require confirmation. The item can appear while the local copy is being prepared and then changes to ready or failed. Deleting the Stash video copy does not affect the original video.

iOS / iPadOS

Folders and multiple files

Folder references are kept locally with access information rather than copied folder contents. When a folder is pasted, Stash may create a temporary ZIP. Multiple copied files are stored locally when their file representations are accessible and restored as multiple file items when pasted.

For folders, use the folder picker or the share sheet when possible; copying a folder in Files and saving it from the clipboard may not provide a reliable folder name or access reference on iOS.

iOS / iPadOS

File copy and text copy

Text-readable files up to 10 MiB (except RTF and SVG) are saved as local file items with both file and text representations. Normal copy lets Files and other file-capable apps receive the file, while Notes and text fields receive the text, so the separate copy-as-text action is hidden. The file item itself is still local-only and is not uploaded to CloudKit, even when a text representation is present. Standalone text copied without a file reference can sync. For a text-readable file over 10 MiB, normal copy remains file-only and the preview card keeps a separate copy-as-text action as a manual fallback. Pasting that text form into a file manager may create a file such as text.txt instead of inserting text inline.

iOS Stash Keyboard

When the iOS keyboard is shown, Stash refreshes the keyboard list order. Snippets are included separately from the history limit. Up to 120 history items, including favorites, are included according to their sort order. Older history items remain available on the home screen. This display limit does not delete or unsync those items.

History limit and device behavior

The history-limit setting is synchronized between devices using the same Apple Account. Automatic trimming caused by that limit is performed separately on each device because local-only items and local history can differ. Automatic trimming does not delete the corresponding shared history from CloudKit or other devices, and increasing the limit does not automatically restore items trimmed on that device. If another device uses a shared history item that was trimmed on this device, its newer last-used date can make it reappear on this device and move to the top of the list. If the limit is already full, another old normal history item may be trimmed instead. Favorites are not included in the normal history limit.

iCloud Sync

If iCloud sync is enabled, eligible data is stored in the user's private CloudKit database associated with their Apple Account. Stash uses the user's private iCloud account and does not send clipboard content to an independent Stash server.

File and folder bodies classified as local references or local-only bodies are not uploaded or displayed on other devices. Their original local file and device-only access information stay on the saving device. Device-only unlock information and local security-scoped access are not synchronized.

Sync settings are controlled per device. Turning off macOS automatic clipboard saving affects only automatic saves on that Mac; it does not turn off iCloud sync or delete existing synchronized items.

Temporary exports and file naming

Folder ZIP files generated for a pasteboard export are temporary. Stash keeps them for up to 10 minutes and removes expired exports; the original folder is not changed.

On iOS, files with the .alac extension are treated as Apple Lossless audio and are shown and pasted with a .m4a name for compatibility. Stash does not re-encode the audio data.

Image format compatibility

When a destination app does not support the original image format, iOS or that app may convert the image to another format, such as PNG or JPEG. Stash provides the saved image data and file representation whenever possible, but the final format is controlled by the destination app. Conversion may remove animation, transparency, or other format-specific properties.

Sensitive Snippets

Sensitive snippets are encrypted before being stored and protected by the app's authentication flow. They are hidden from ordinary lists and preview cards to reduce accidental exposure. This feature is not a replacement for a dedicated password manager.

Passwords, derived encryption keys, and device-only unlock information are not synchronized as ordinary clipboard data. The user is responsible for deciding what sensitive information to save in Stash.

Analytics and Tracking

Stash does not include analytics, advertising, telemetry, or third-party tracking code.

Data Sharing

Stash does not sell user data and does not share clipboard data with third parties. Data is transmitted only when the user uses an operating-system sharing or pasteboard workflow, or when the user enables iCloud synchronization.

User Control and Deletion

Users can delete history items, snippets, favorites, and stored data from within the app. Deleting a Stash item removes Stash's copy or metadata record and any supported synchronization record; it does not delete the original file or folder from the user's device or Finder.

Temporary export files used to provide file paste follow the platform's temporary-file lifecycle. The original source remains under the control of the operating system or source application.

Contact

For privacy questions or support requests, please contact output@unwraps.net.

データの取り扱い

Stashは、ユーザーの端末上でクリップボード履歴とスニペットを利用できるようにします。このページでは、端末内保存、プライベートiCloud同期、ファイル参照メタデータの違いを説明します。

Stashが保存するデータ

Stashは、ユーザーが保存することを選択したクリップボード履歴、スニペット、お気に入り、テキスト、リッチテキスト、画像、ファイル参照、フォルダ、複数コピー、メディアのメタデータなどを扱います。クリップボードの内容は、標準ではユーザーの端末にローカル保存されます。

macOSでは、自動保存スイッチは端末ごとの設定です。オフにすると、そのMacで新しくコピーした項目は自動的な履歴保存の対象になりません。スニペット保存など、ユーザーが明示的に行う操作は引き続き利用できます。

権限と端末アクセス

iOSでは、StashはユーザーがStashを開いた時、または保存・ペーストの操作を行う時に一般ペーストボードを読み取ります。iOSでペースト許可が表示される場合があります。Stashがバックグラウンドで全てのコピー操作を監視することはありません。

macOSでは、自動ペーストのためにアクセシビリティ権限を使い、直前に使用していたアプリへCommand-Vを送信します。この権限はそのペースト操作に使用され、クリップボード内容をStashのサーバーへ送信するためには使われません。

macOSでTouch IDによる解除を有効にした場合、端末内の解除キーはそのMacのキーチェーンに保存され、同期されません。秘密スニペットの復号は引き続き端末内の認証フローに依存します。

3つの保存分類

01 / 本体

Stash内に本体が保存されるもの

一部のテキスト、リッチテキスト、対応画像は、OSごとのサイズ・種類のルールに従ってアプリ内に保存されます。同期対象になるテキスト、リッチテキスト、画像のペイロードはiCloudにも同期されます。動画、音声、読み込んだファイル本体は端末内だけに保存されます。

02 / 端末内のみ

本体は端末内に保存されるが、同期されないもの

大きなデータやプラットフォーム固有の本体データの一部は、取得・保存した端末だけに残ります。CloudKitにはアップロードされません。

03 / 参照

本体ではなく参照メタデータだけが保存されるもの

多くのファイル、フォルダ、パッケージ、アーカイブ、メディア、フォント、Office/iWork書類、コードファイルなどでは、元の本体をコピーせず、参照専用のメタデータを保存します。これらは保存元端末にだけ残り、CloudKitへアップロードされず、他端末にも表示されません。メタデータには、表示名、拡張子、種類、コピー元アプリや端末、元URL、取得できる場合のセキュリティスコープ付きアクセス情報などが含まれます。

項目ごと

拡張子だけでは決まりません

本体保存かメタデータのみかは、履歴項目ごとに判定されます。同じ拡張子でも、コピー元がテキスト、画像、ファイル参照のどれを提供したかで分類が変わる場合があります。

プレビューに表示されるバイト数は、Stash内に本体を保存している項目では保存された本体のサイズです。メタデータのみの項目では、元ファイルのサイズではなくメタデータ記録自体のサイズです。

OSごとの違い

macOS

ファイル参照はコピー元Macに紐づきます

対応形式で100MB以下の画像は画像データとして保存され、同期対象になる場合があります。PDF、SVG、アーカイブ、フォント、音声、動画、Office/iWork書類、フォルダ、パッケージ、コード・テキストファイルなど、多くのファイル履歴は本体をStashへコピーせず、元の場所へのメタデータとローカルアクセス情報を保持します。10MBを超えるリッチテキストは端末内に保持し、プレーンテキストは同期できる場合があります。

iOS / iPadOS

アクセスできるファイル本体を端末内に保持できます

iOSがアクセス可能なファイルURLまたはファイル表現を提供する場合、PDF、SVG、アーカイブ、フォント、音声、動画、Office/iWork/OpenDocument書類、EPUB、コード・テキストファイルなどをStashの端末内ストレージへコピーできます。これらはその端末でのペーストに使われますが、他端末へはアップロードされません。動画と音声は端末内のみです。

動画の保存には確認が必要です。ローカルコピーの準備中も項目が表示され、完了または失敗の状態に変わります。Stash内の動画コピーを削除しても、元の動画には影響しません。

iOS / iPadOS

フォルダと複数ファイル

フォルダは内容をコピーせず、アクセス情報を持つローカル参照として保持します。フォルダをペーストすると、一時ZIPを生成する場合があります。複数ファイルはアクセス可能なファイル表現がある場合に端末内へ保存され、ペースト時に複数のファイル項目として復元されます。

フォルダは、できるだけフォルダ選択または共有シートから保存してください。Filesでフォルダをコピーしてクリップボードから保存すると、iOSではフォルダ名やアクセス参照を安定して取得できない場合があります。

iOS / iPadOS

ファイルとしてコピー・テキストとしてコピー

10MiB以下の文字として読めるファイル（RTFとSVGを除く）は、ファイル表現とテキスト表現の両方を持つ端末内専用のファイル項目として保存されます。通常のコピーでは、Filesなどファイル対応アプリにはファイルとして、メモやテキスト欄にはテキストとして渡されるため、別の「テキストとしてコピー」操作は表示されません。ただし、ファイル項目自体はCloudKitへアップロードされず、テキスト表現があっても端末内だけに残ります。ファイル参照を伴わずにコピーした通常のテキストは同期対象になります。10MiBを超える文字として読めるファイルは通常コピーではファイル表現のみとなり、プレビューカードに手動の「テキストとしてコピー」操作が残ります。そのテキスト形式をファイラーへ貼ると、本文ではなく text.txt などのファイルが作られる場合があります。

iOS Stashキーボード

iOSのStashキーボードを表示すると、キーボード一覧の履歴の並び順が更新されます。スニペットは履歴上限とは別に表示されます。履歴はお気に入りを含めて、並び順の上位120件まで表示されます。120件より後の履歴もStash本体のホーム画面では引き続き利用できます。この表示上限によって項目が削除されたり、同期されなくなったりすることはありません。

履歴上限と端末ごとの挙動

同じApple Accountを使用する端末間では、履歴上限の設定値が同期されます。上限による自動削除は、ローカル専用項目や端末内の履歴が異なるため、端末ごとに個別に行われます。自動削除では、CloudKitや他端末の対応する共有履歴は削除されず、上限を増やしてもその端末で自動削除された項目は自動復元されません。別端末で、この端末で自動削除された共有履歴が使用されると、使用日時の更新によってこの端末に再表示され、一覧の先頭に戻る場合があります。上限に達している場合は、代わりに別の古い通常履歴が自動削除されることがあります。お気に入りは通常履歴の上限に含まれません。

iCloud同期

iCloud同期を有効にすると、同期対象のデータはユーザーのApple Accountに紐づくプライベートCloudKitデータベースに保存されます。Stashはユーザー自身のプライベートiCloudを使用し、独自のStashサーバーへクリップボード内容を送信しません。

ファイルやフォルダの本体、端末内のみ保存される本体はCloudKitへアップロードされず、他端末にも表示されません。元のローカルファイルと端末専用のアクセス情報は保存元端末に残ります。端末専用のロック解除情報やローカルのセキュリティスコープ付きアクセス情報も同期されません。

同期設定は端末ごとに管理されます。Macの自動保存をオフにしても、そのMacでの自動保存が止まるだけで、iCloud同期が停止したり既存の同期項目が削除されたりすることはありません。

一時書き出しとファイル名

ペーストボードへ渡すために生成されたフォルダのZIPは一時ファイルです。Stashは最長10分保持し、期限切れの書き出しを削除します。元のフォルダは変更しません。

iOSでは、.alac拡張子のファイルをApple Lossless音声として扱い、互換性のため.m4aの名前で表示・ペーストします。Stashは音声データを再エンコードしません。

画像形式の互換性

貼り付け先アプリが元の画像形式に対応していない場合、iOSまたは貼り付け先アプリがPNGやJPEGなど別の画像形式へ変換することがあります。Stashは可能な限り保存した画像データとファイル表現を渡しますが、最終的な形式は貼り付け先アプリの仕様で決まります。変換により、アニメーション、透明度など形式固有の情報が失われる場合があります。

秘密スニペット

秘密スニペットは保存前に暗号化され、アプリの認証フローで保護されます。意図しない露出を減らすため、通常の一覧やプレビューカードには表示されません。この機能は専用のパスワードマネージャーの代替ではありません。

パスワード、暗号化キーを導出する情報、端末専用のロック解除情報は、通常のクリップボードデータとして同期されません。Stashにどのような機密情報を保存するかは、ユーザー自身の判断と責任で行ってください。

解析・トラッキング

Stashには、解析、広告、テレメトリ、第三者トラッキングのコードは含まれていません。

データの共有

Stashはユーザーデータを販売せず、クリップボードデータを第三者と共有しません。外部へ渡るのは、ユーザーがOSの共有・ペーストボード機能を使った場合、またはiCloud同期を有効にした場合です。

ユーザーによる管理と削除

ユーザーは、アプリ内から履歴、スニペット、お気に入り、保存データを削除できます。Stashの項目を削除すると、Stash内の本体またはメタデータ記録と対応する同期記録が削除されますが、端末上やFinder上の元ファイル・元フォルダは削除されません。

ファイルとしてペーストするための一時書き出しファイルは、OSの一時ファイルのライフサイクルに従って整理されます。元データはOSまたはコピー元アプリの管理下に残ります。
